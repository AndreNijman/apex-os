# The shell is accessible on the new image — 8 windows on the bus, no shim

Measured on katana 2026-09-22, on the image built that night
(`apex-44c9a5cb…`, digest `sha256:06ba23c3…`), in a real Hyprland session
started the way `katana-qualification-20260919.md` §4 documents.

## The result

```
applications on the AT-SPI bus: 4
  :1.0    polkit-mate-authentication   ChildCount=0
  :1.2    xdg-desktop-portal-gtk       ChildCount=0
  :1.34   polkit-mate-authentication   ChildCount=0
  :1.35   quickshell                   ChildCount=8
```

**Eight.** P2-003 has said for rounds that "on a real machine a screen reader
still gets ONE node from the shell". It now gets a tree.

That number is not new — round 30 measured exactly 8 by interposing
`QGuiApplication::exec()` with an `LD_PRELOAD` shim that reinstalled QtQuick's
accessibility factory. The shim "is test-only and ships nowhere". **The same 8
now appears with no shim**, from the shipped binary, because
`quickshell-git 0.3.1^860.gitc6a5160` carries upstream commit `916a0dd`
("launch: avoid creating multiple QApplications").

## The positive control, and why it is load-bearing

`soffice` published `ChildCount=2` in the first run of this probe, while
quickshell published 0. So the bus, the registry and the probe were all working
at the moment quickshell answered zero — the zero was about quickshell, not
about the instrument. LibreOffice was only on the machine at all because it had
been installed hours earlier for P1-038.

## A REAL FINDING: the bridge must be on BEFORE the shell starts

The first measurement on this same image, same binary, same session, read
**`quickshell ChildCount=0`** — and it would have been reported as "the fix does
not work" if it had been trusted.

The difference is startup order:

| | `toolkit-accessibility` at quickshell start | result |
|---|---|---|
| first run | `false` (turned on afterwards) | **0** |
| second run | `true` | **8** |

Qt decides whether to publish when the application object is built. Turning the
bridge on later does not retrofit it. So on a machine where
`org.gnome.desktop.interface toolkit-accessibility` is false at login — which is
the **default** — the shell ships an empty tree no matter which quickshell is
installed.

**This is the next thing P2-003 needs, and it is APEX's to fix, not upstream's.**
Either the session sets `QT_LINUX_ACCESSIBILITY_ALWAYS_ON=1` for the shell, or
the image ships the gsetting on. Neither is done today: quickshell's environment
on this machine carried no accessibility variable at all.

## What this closes and what it does not

- **Closes:** "a screen reader gets one node", the runtime half P2-003 has been
  blocked on, and it closes it without the shim.
- **Does not close:** whether the *content* is good — names, roles, focus order.
  `ChildCount=8` says eight windows are on the bus, not that a blind user can
  drive the shell. The lock screen's password field, which
  `check-lockscreen-a11y.sh` asserts at source level and could never reach at
  runtime, is now reachable and worth measuring properly.
- **Does not close:** Orca at the greeter, which is a different session.
