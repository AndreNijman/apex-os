### Sequencing notes for whoever picks this up
- **Stop `apex-wip-snapshot.timer` before rewriting** and restart it after. It
  pushes every dirty worktree to `refs/wip` every three minutes and would race a
  rewrite. It is running right now, deliberately — it is the backup safety net.
- **Do the rewrite in a fresh mirror clone, not in place.** There are ~40 live
  worktrees sharing each repo; `filter-branch` in place would fight all of them.
  Rewrite the mirror, verify, force-push, then re-point `int-os` and `int-shell`.
- `git filter-repo` is **not installed**. Plain `git filter-branch` with
  `--env-filter` (identity), `--msg-filter` (strip trailers) and
  `--commit-filter` calling `git commit-tree -S` does all three in one pass and
  preserves merge commits, which a `rebase --root` would flatten.

Three fixes:

1. **Window border — a startup race, not a missing feature.** `WallpaperService`
   retinted from `Component.onCompleted`, but `Theme.active` is bound through
   `ColorLoader`, a file watcher on matugen's `colors.json`, so at that moment it
   is usually still the built-in default. The border was set once from a palette
   that had not loaded, then never again until the next wallpaper change. It
   follows the property now. (The `Connections` had to be wrapped in a
   `property var` — the root is a `QtObject` with no default property, so a bare
   child is silently dropped. `qmllint-qt6` caught that.)
2. **Top-left icon** — a fixed chartreuse PNG drawn raw. `MultiEffect` with
   `colorization: 1.0` recolours it to `Theme.active`.
3. **fastfetch** — four hardcoded `{#38;2;161;201;153}` escapes became `{#keys}`,
   the one colour `--color` can override. New matugen template
   `shell-accent.template` renders the accent as a ready SGR string to
   `~/.cache/apex-shell/accent-ansi`; `apex-greeting.sh` reads it, validates it to
   digits and semicolons, and passes `--color`. Verified end-to-end: the whole
   greeting renders peach.

**Plymouth was dropped on Andre's instruction** ("ok dont do plymouth then").
Worth recording why it was raised: the theme is baked into the initramfs
(confirmed, 12 entries in the booted initrd), plymouthd loads it once before
switch-root, and its script language has no file I/O — so a boot splash that
tracks the wallpaper would mean a new deployment per wallpaper change.
