## FOUND
- **Andre's GitHub PAT is 23 bytes and matches no GitHub token shape.** The
  plugin:github MCP server fails with "Authorization header is badly formatted",
  which is consistent with a stale value. Nothing was sent anywhere. A real
  migration would store it under `github` BEFORE verifying, and the git shim
  tries `github` first for any http remote — so a dead token becomes a 401 on
  push rather than a fall-through. Fix: `apex secret remove github`, or replace
  the token.
- **`APEX_REQUIRE_APEX_CLI` is read by nothing in this tree.** The variables
  that actually turn a skip into a failure are `APEX_REQUIRE_SANDBOX`,
  `APEX_REQUIRE_SHELL_TREE` and `APEX_REQUIRE_NIRI`. Stop putting it in agent
  prompts. The property it was meant to give is available anyway:
  `grep -c '#\[ignore' apexd/` is 0 and every `test result` line reports
  `0 ignored`, so no cargo test can skip silently.
- **MCP grants are per-project, MCP servers are global.** Every new worktree has
  an unauthorised memory server until someone grants it there. A `"*"` project
  key would fix it in a few lines; not done, because it is a policy widening.
- `gh` inside a session says "You are not logged into any GitHub hosts" —
  measured, not inferred — because `~/.config/gh` is not in the profile table.
  True before this change and after it. Outside a session `gh` is untouched.
