1. With no flag, **all four** surfaces start a server: `~/.claude.json`
   `mcpServers`, `~/.claude.json` `projects.<dir>.mcpServers`, the working
   directory's own `.mcp.json`, and an enabled plugin's `.mcp.json`.
2. With `--strict-mcp-config --mcp-config <file>`, **only the file's servers
   start** — the plugin-defined one is dropped along with the rest. That is the
   mechanism P1-026's second criterion needs and `sidecar.rs` already named.
3. A server key containing `:` (`plugin:fakeplug:plugsrv`) is accepted verbatim
   in a `--mcp-config` file, so a curated document can keep the agent's existing
   spelling — and therefore the `mcp__<server>__<tool>` names any permission rule
   already refers to.
4. A plugin's live `.mcp.json` is the copy under `installed_plugins.json`'s
   `installPath` (`plugins/cache/<mp>/<plugin>/<version>`), not the marketplace
   checkout. `servers::enabled_plugin_configs` already reads the right one; a
   fixture that points installPath at the checkout measures a stale file.
5. Repo `.mcp.json` servers are approved per directory
   (`enabledMcpjsonServers` / `disabledMcpjsonServers` in the project entry), and
   `-p` skips the trust dialog. A curated document that listed an unapproved one
   would be APEX approving it on the user's behalf.

### What is left, and why

- **P1-026 criterion 2 stays architecturally short, and the shortfall moved.**
  It is no longer "MCP servers are confinable only if somebody wrapped them" —
  the launcher wraps every third-party one. It is now: (a) that confinement
  exists only on the `apex agent` path and only for an adapter with
  `strict_mcp` (today `claude`), and (b) a plugin's HOOKS and shipped scripts
  are run by the agent itself and get no sandbox of their own — they inherit
  the session's. Claude Code has `--safe-mode` (every customization off,
  including plugins and hooks) and `--bare` (skip hooks and plugin sync), which
  would let a hardened profile remove that content rather than confine it.
  **Deliberately not wired this round**: it is another policy dimension, which
  means another protocol version bump, and it needs a live hook-escape test to
  be anything but a grep.
- **P1-028 criterion 1's shell half.** `apex-shell` has no connector surface at
  all — `grep -rl mcp src/` in apex-shell returns nothing. The security readout
  that distinguishes the planes is the CLI (`apex mcp planes`, `apex mcp list`,
  `apex provenance show`). If a dashboard section is wanted it goes on
  `task/p1-025-plugin-trust-shell` in an apex-shell worktree, reading
  `apex mcp planes --json`, alongside `AgentCenter.qml`.
