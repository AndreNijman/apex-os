## Criteria, quoted from roadmap.yaml

1. Automated tests simulate power loss during update, full disk, network loss,
   shell/apexd crashes, expired cloud token, killed agent during checkpoint,
   monitor hot-unplug, suspend during work, and failed rollback.
2. Boot/update/install/rollback loops run continuously in VMs.
3. Failures produce reproducible diagnostics and do not silently corrupt the
   installation.

## What this program has already learned that belongs in this harness

Every one of these is a real incident from this repository's history, and each
is a chaos case that would have caught it:

- **A staged ostree deployment is discarded by a crash before clean shutdown.**
  "Updated but nothing changed" is that, and it is exactly criterion 1's power
  loss during update. The machine must come back on the old image and *say so*.
- **`apex install` builds a sysext that merges live**, and a hotfix overlay
  reverts on reboot while `apex-user.raw` persists. A reboot loop must assert
  which of those two survived.
- **A test that cannot run must say so.** Two assertions that could never run
  or never fail kept `roadmap/v2.2` from producing an image for five days. A
  chaos harness that reports "no corruption" when it never managed to inject
  the fault is the same defect with higher stakes — every case needs a verdict
  with a could-not-inject arm, not a boolean.
- **The runner is a different environment** from this laptop: OpenSSL 3.0.13 vs
  3.5.7, no `/etc/localtime`, no CAP_NET_ADMIN over a real netns. If a case
  needs a kernel interface, get it with `unshare --user --map-root-user --net`
  or say the case could not run.

## Constraints that shape the design

- **Headless, always.** No window on Andre's desktop. VMs run with no display;
  qemu with `-nographic`/`-display none`, or libvirt with no graphics device.
- **This laptop is the only machine.** katana is off-limits. GitHub CI is the
  second environment, and a "continuous" loop there is a scheduled workflow,
  not an infinite one — design for a bounded run with a resumable cursor.
- **Never touch the live machine's boot path.** No `bootctl install`, no
  `rpm-ostree` against the host, no `apex update` outside a VM. The image build
  already asserts that nothing in its payload does; your harness must be held
  to the same rule and should assert it about itself.
- There is a rollback staged on this laptop right now waiting for Andre to
  reboot (`ROADMAP/evidence/P0-001-rollback-staged.md`). Do not disturb it.

**Defects the harness found and fixed, each caught by a case before it was
fixed:**
- `channel.rs` `read_record` returned `Option`, so a torn update record printed
  "nothing recorded yet" for a machine that had just updated. Now
  `Result<Option<_>, String>`; `lastUpdate` and `lastUpdateError` are separate
  JSON fields. `record_update` is temp-and-rename.
- `main.rs` `apex doctor`'s metrics probe collapsed ENETUNREACH and
  ECONNREFUSED into one sentence — a machine with no networking was told its
  endpoint is not reachable, out of a syscall that never left the box.
- `qualify::save` left a 0644 `qualification.json.tmp` on a full filesystem: it
  removes the temp on rename failure, not on write failure, and the
  `set_permissions(0600)` sits between the two. Now `OpenOptions::mode(0o600)`
  at creation plus removal on failure. `channel::record_update` got the same.
- `lib.sh`'s fixture-root rule was a comment describing a helper no case
  called.

**Nine other temp-then-rename writers were surveyed and NOT changed** —
`apex/src/{host,task,blueprint}.rs`, `apex-agent-core/src/{config,checkpoint,
project,request}.rs`. Listed in `full-disk.sh`'s header. A case that drives one
of them is the way to close them.

### Left for a human decision, not an agent's

`boot-v2.yml`'s chaos series is **opt-in, default 0 iterations**, so it does
nothing on a PR. Making it genuinely periodic is one line — a `schedule:`
trigger beside `workflow_dispatch`. That line was deliberately not added: a
cron is a recurring CI bill, and `docs/update-cost.md` is this repository's
record of taking that seriously. **Andre decides.** Each iteration is roughly a
minute with KVM.
