## Vectors (FOUND — do not re-derive)

Fetched to `/var/tmp/apex-work/fido-vectors/`. Each was verified by hand with
`openssl pkeyutl -verify -pubin -keyform DER -rawin -digest sha256` over
`authData || cdh` before a line of Rust was written.

- **libfido2 `regress/assert.c`** (Yubico's own regress suite, real device).
  `flags = 0x00` — a silent assertion, `fido_assert_set_up(FIDO_OPT_FALSE)`.
  Verifies. It is therefore the one thing a fabricated vector cannot be: a
  cryptographically valid assertion with **no user presence**. Use it as the
  negative for the UP requirement, not as the positive.
- **go-webauthn `protocol/assertion_test.go`, `testAssertionSpecVectorNoneES256`**
  — `flags = 0x19` (UP+BE+BS), counter 0, rp `example.org`. Verifies.
- **go-webauthn `testAssertionResponses["success"]`** — macOS TouchID via
  webauthn.io, `flags = 0x45` (UP+UV+**AT**), counter 1553097241, authData 187
  bytes with the credential key embedded. Verifies against that embedded key.
  Forces the design choice: parse the first 37 bytes, require `len >= 37`, do
  not reject trailing bytes.

Tool I/O shapes, read out of libfido2's `tools/` rather than assumed:

- `fido2-assert -G` prints four lines: base64 cdh, rp id, base64
  **`fido_assert_authdata_ptr`** — the CBOR bstr, i.e. `0x58 0x25 …`, not the
  raw 37 bytes — and base64 DER signature.
- Its first *input* line is the client data **hash** by default; `-w` (FLAG_CD)
  makes it raw client data that libfido2 hashes itself. Both produce
  `cdh = sha256(challenge)`. `-p` is what demands the touch.
- `fido2-cred -V` prints base64 credential id, then a **PEM SPKI** public key
  (`write_es256_pubkey`), not a raw COSE key. Import must accept that.

  `CARGO_TARGET_DIR`, `XDG_STATE_HOME`, `XDG_CONFIG_HOME`. Env script:
  `/var/tmp/p0-014-env.sh`.

  run looks like it produced no tests at all.
