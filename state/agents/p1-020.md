- SessionInfo (apex-os apexd/apex-agent-core/src/protocol.rs:147) has NO parent
  field. The runtime has no notion of a subagent, so P1-020's graph has to be
  DERIVED from evidence, not read from the daemon.
- Sandboxed sessions run under `bwrap --unshare-pid`, but the host /proc still
  sees every descendant. The process tree is therefore the one evidence source
  that works for every adapter.
- Claude subagents are in-process (one API loop, no fork), so they never appear
  in /proc at all.
- LIVE DEFECT, P1-022: AgentService._notifyProc is a single Process and _notify
  runs `notify-send --wait`, which blocks until the notification is dismissed.
  Quickshell ignores a `command` change on a running Process and `running=true`
  is a no-op while it runs, so EVERY notification after the first is silently
  dropped until the user dismisses the first. Observed live: pid 1241444 has
  been blocked ~4.9 hours on 'Claude is waiting for you' for session 6.
