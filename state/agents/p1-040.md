## MEASURED: QtQuick's `Screen` attached property resolves per window
Probed headlessly on the two-output harness (quickshell 0.3.1, labwc backend):
- at `Component.onCompleted` an Item inside the HEADLESS-1 PanelWindow reports
  `Screen.name=HEADLESS-2 Screen.height=1080` — the WRONG screen, and
  `Window.window` is null. The item is not on its output yet.
- at t=2500ms the same item reports `Screen.name=HEADLESS-1 Screen.height=2160`
  and the HEADLESS-2 item reports 1080. Correct, per window, with no plumbing.
This is the mechanism a per-output factor would use: `Screen.height` is the
LOGICAL height of the output the item is actually displayed on, which is exactly
the input `scaling.js:scaleForHeight()` already takes.
