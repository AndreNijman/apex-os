# p1-053b — Android Projects/Workspaces/Worktrees/Tasks/Review UX

items: P1-056, P1-057, P1-058

## START FROM THIS CONSTRAINT — it is measured, not assumed

p1-053a finished and landed as merge `4ae4cf22`. Its closing finding is the
thing P1-056 has to be designed around:

**`apex-agent-core`'s `Request` enum has NO `profile` verb, NO `projects` verb
and NO `worktrees` verb.** That was read out of the enum, not remembered.
Round 3 of p1-053a had built a `{"cmd":"worktrees"}` request and a parser for
the answer; nothing on the other end could ever have parsed it, and the phone
would have shown an error where it offered a picker. It was removed, and a test
was kept and INVERTED so it cannot come back.

So a Projects/Workspaces/Worktrees UX either:
  (a) derives what it shows from what the daemon already reports
      (`Hello.agents`, and `RunRequest.worktree` does exist as a NAME), or
  (b) adds the verbs to the daemon — which is a protocol change, needs the
      desktop side, and is a much bigger unit than it looks.

Decide which, say so on the branch, and do not build a picker over a verb that
does not exist. If you choose (b), the socket's own tests are where it starts.

## Constraints that have already bitten this codebase

- **Every socket write must be off the main thread.** Android installs
  `StrictMode.enableDeathOnNetwork()` for every app targeting API 11+. It is
  not a flag and a debug build does not relax it. The first keystroke would
  have killed the process. Terminal io is on a single-thread executor (single,
  because a pool delivers `ls` as `sl`); view-model closes go to
  `Dispatchers.IO`. Nothing here can catch a regression: no JVM test reaches a
  Compose callback, and `assembleDebug` compiles code it never runs. Read for
  it.
- **NO device and NO emulator.** Headless only. `./gradlew :core:test
  :app:testDebugUnitTest :app:assembleDebug` with
  `JAVA_HOME=/usr/lib/jvm/java-21-openjdk ANDROID_HOME=/var/tmp/android-sdk`.
  Never open a window on Andre's desktop.
- The CI `android` job **has still never run**. Its path classifier has been
  run by hand against a diff; that is not the same thing.
- Mutation discipline: every new assertion must be watched going red against a
  mutated source, and the source restored **byte-identical with plain `cp`** —
  never `mv`, never `cp -p`; both preserve mtime and cargo/gradle then skip the
  rebuild, so the "restored" run is the mutant's own cached result.

## THE STARTING CONSTRAINT WAS FALSE — measured 2026-09-12, round 1

**`apex-agent-core` DOES have a `worktrees` verb**, and has since `473b7f60`
(2026-09-08), which is an ancestor of `roadmap/v2.2`.

* `apexd/apex-agent-core/src/protocol.rs:723` — `Worktrees { project:
  Option<String> }` on the `#[serde(tag="cmd", rename_all="snake_case")]` enum.
* `apexd/apex-agentd/src/main.rs:906` dispatches it; no origin gate.
* `apexd/apex-remoted/src/serve.rs:473` — the proxy is a DENYLIST of one verb
  (`attach`), so a paired phone reaches it.

The mistake: `apex-agent-core` has TWO types named after requests.
`request.rs`'s `Verb` is the PRIVILEGED OPERATION vocabulary (install, remove,
pkg-*, pin, rollback, update) and has no worktrees/projects/profile — correctly.
`protocol.rs`'s `Request` is the WIRE and has 28 verbs. The claim was read off
the first. `profile` and `projects` really are absent; that half was right.

**This also means `roadmap.yaml`'s P1-054 evidence carries the false claim**,
and so does p1-053a's card. Those are records and were not rewritten; the
correction lives on `task/p1-053b-android-ux` commit `ca453ea3` and here.

Decision recorded in that commit: **(c) — neither (a) nor (b). The verb was
already there.**

## The live daemon is OLDER than the verb

`rpm-ostree status` on this L16: image `apex (2026-09-05T13:36:24Z)`. The verb
landed 09-08. So every `worktrees` request against the *live* machine answers
`{"reply":"error","kind":"bad_request","message":"unparseable request: unknown
variant `worktrees` ..."}`. `Agentd.isTooOld` tells that apart from a real
refusal, which is also `bad_request`. Do not read an empty list from it.

## P1-057: a phone can NEVER approve a root operation, and every verb is root

`apexd/apex-agentd/src/privilege.rs:1176` refuses `decide` from any non-local
origin unconditionally — before the Pending check, so a phone cannot even DENY.
`Request::Decide` has no `second_factor` field and `decide` never consults
`OriginPolicy`. `apex-remoted` declares `claude-remote-control`
(`proxy.rs:128`), which is not local. Pinned by
`apexd/apex-agentd/tests/request_origin.rs:369`.

`request.rs:290` maps ALL EIGHT verbs to `Capability::RootCapability`. So there
is no non-root approvable object on this socket at all. `GitHubPush`,
`CloudflarePreviewDeploy` and `ProductionDeploy` exist only as rows in §7's
table (`origin.rs:842`) with `#[derive]`d no serde — `Capability` never appears
on the wire and nothing in this build performs them.

Production-deploy approval DOES exist, on a DIFFERENT daemon: `apex-secretd`,
tag key `"op"`, kebab-case (`apex-secret-core/src/protocol.rs`). **`apex-remoted`
never connects to it** — grep confirms no secretd socket path in its sources.

What a phone CAN do: `requests`, `grants`, `system_grants` (all ungated),
`revoke` and `revoke_system_grant` (session-gated only, NOT origin-gated), and
`elevation_challenge`. `renew_system_grant` works remotely only with
`remote_elevation_allowed` + a UV-verified (PIN/biometric) key.

## P1-058: there is no push transport anywhere

No FCM/Firebase/UnifiedPush/ntfy anywhere in the repo, `android/` included. No
subscribe/watch verb on the socket — the phone polls `{"cmd":"list"}` every 4 s
(`RemoteViewModel.kt:578`) and only while the Agent Center is on screen. The
relay is a stateless byte-copier that **has never been deployed**
(`relay/README.md:11`), both ends dial out, and the wire has no notification
frame. `AndroidManifest.xml` has no `POST_NOTIFICATIONS` and no service.

Other measured facts for P1-058:
* `complete` is effectively UNREACHABLE for interactive Claude: it comes only
  from exit code 0, and the adapter runs claude interactively. "Turn finished"
  arrives as `waiting_for_user`.
* The duplicate pair is APEX-INTERNAL, not Claude-vs-APEX: four paths publish
  `waiting_for_user` for the same moment (hook `notification`, hook `stop`, the
  PTY BEL/OSC scanner, and the 10 s idle rule), and `Session::set_state`
  (`registry.rs:163`) has no same-state early return. Dedup must be client-side
  on `(machine, id, state)` transition edges.
* Session `id: u32` is REUSED after `prune` (`registry.rs:441`), so a stale
  notification can open the wrong session. It is also per-machine, not global.
* `SessionInfo.detail` copies Bash command lines, file paths, grep patterns,
  URLs and Claude's own notification text verbatim (`hook.rs:437`). It must
  never leave the device.

### Verbs measured this round, so nobody re-derives them

* **`Input { id, data }` EXISTS and a phone may use it.**
  `privilege::refuse_input` (`privilege.rs:326`) refuses exactly two callers: a
  connection that IS a managed session, and one whose origin could not be
  classified. `apex-remoted` is neither. This is the input-needed workflow.
* **`Input` landed 2026-09-08 (`8c3958df`), the same day as `Worktrees`
  (`473b7f60`).** The L16's image is 2026-09-05, so BOTH happy paths are
  unreachable on this machine and both take `Agentd.isTooOld`.
* **There is no checkpoint verb on the socket.** Not list, not restore, not
  undo. `checkpoint::list`/`restore` exist in `apex-agent-core` and their only
  non-test callers are in `apexd/apex/src/agent.rs`, the CLI, on the local
  filesystem. `RunRequest.checkpoint` (ask for one) and `SessionInfo.checkpoint`
  (the id of the one taken) are the whole wire surface.
* **`Inject`, `Decide`, `Telemetry`, `ToolCheck`** were checked and are not
  what P1-057 needs: `Decide` is refused from any non-local origin
  unconditionally, and the other three are agent-side plumbing.

### What is left, and it is not Android work

1. **P1-057 criteria 1 and 2 need a protocol change.** `Capability` never
   appears on the wire — `GitHubPush`, `CloudflarePreviewDeploy` and
   `ProductionDeploy` are rows in §7's table (`origin.rs:842`) with no serde
   derive, and nothing in this build performs them. Production-deploy approval
   DOES exist on `apex-secretd`, and `apex-remoted` never connects to it (no
   secretd socket path in its sources). Until a non-root approvable object is
   on this socket there is nothing for a phone to approve.
2. **P1-057 criterion 4 is a separate unit: `RenewSystemGrant` +
   WebAuthn.** It is the only path in this build with the right shape
   (`remote_elevation_allowed` + a UV-verified key). `SubmittedFactor` wants
   "the four lines `fido2-assert -G` printed, verbatim", and enrolment is
   `fido2-cred -M -t es256` on the machine pasted into `apex agent key add`.
   An Android phone would have to act as a FIDO2 authenticator producing that
   exact libfido2 text and be enrolled out of band. `AppLock` is a local
   Keystore biometric and is NOT that. Do not fold this into an Android round.
3. **P1-056's checkpoint/undo consequences need a checkpoint verb.** What a
   restore would change is computed on the machine from the checkpoint's tree;
   none of it crosses this wire.
4. **The CI `android` job has still never run.**
