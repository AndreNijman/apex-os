## FOUND — for P1-044, not fixed here

Measured in a network namespace with the shipped `apex.nft` loaded, three
namespaces wired client — router — server, `ip_forward=1` on the router. Each
result is paired with a positive control (mDNS on 5353 arriving) so that
"silent" cannot mean "the harness sent nothing".

1. **A Wi-Fi hotspot cannot work under this policy, in three independent ways.**
   NetworkManager's shared mode runs dnsmasq and NATs; all three legs are shut.
   - `forward` is `policy drop`, so no client packet is routed. Measured:
     forwarding succeeds before the ruleset loads and stops after it.
   - The only DHCP rule is `udp sport 67 udp dport 68`, the **reply**
     direction. A hotspot client broadcasts a DISCOVER to `dport 67`, a new
     flow, so `established,related` cannot rescue it. Measured: silent.
   - `udp dport 53` is shut, so dnsmasq resolves nothing for clients.
     Measured: silent.
   A fix wants interface-scoped rules on the shared link, which the port-only
   exception catalogue cannot express. This is adjacent to the card's item 4.

2. `nft add element inet apex allowed_tcp { 631 }` reopens 631 immediately, so
   the exception mechanism itself is sound. Verified for 445 and 2049 too.

## Defects found live, not in any task description

1. **`scanimage -L` never returns on the shipped image.** It hangs after
   initialising hplip's `hpaio` backend (`SANE_DEBUG_DLL=4` shows it as the
   last one loaded; the process sits in `rt_sigsuspend` with no children and
   no sockets). Commenting `hpaio` out of `/etc/sane.d/dll.d/hpaio` makes it
   return in 7 s **and find a real scanner** — `airscan:w1:CANON INC. TR4600
   series` at 192.168.1.121 over WSD. So the image can scan and hplip stops it.
   Any scan UI that enumerates devices hangs at startup.

2. **`avahi-daemon.service` and `.socket` are masked** on the L16
   (`/etc/systemd/system/avahi-daemon.{service,socket} -> /dev/null`, 6 Sep
   08:41, owned by no package). `Containerfile.core:1040` builds the whole
   driverless-print story on the claim that "avahi is already installed AND
   enabled in this image (verified)", and no build step asserts it. A mask in
   `/etc` survives every image update and nothing reports it.

3. Thunderbolt on the L16: `domain0`/`domain1` are `security=user` with
   `iommu_dma_protection=1`. `security=user` means an attached device stays at
   `authorized=0` until something authorises it, and `bolt` is not installed,
   so a USB-C dock behind a TB controller is dead with no message.

4. `Containerfile.core:1003` says "there is no `gvfs-archive` subpackage".
   `dnf5 repoquery` finds `gvfs-archive-1.58.4-4.fc43`. The comment is stale.
