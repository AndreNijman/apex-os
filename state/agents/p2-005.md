3. **`apex devices network` reported a working machine as two blockers.** It
   stated the firewall's policy as fact — "the firewall drops forwarded traffic"

   `connectivity  Error: Could not create NMClient object…` — and then explained
   that NetworkManager "answers '<that error>' for any connected link". `links`,
   ten lines above, already refused to do this. The rc was thrown away.
5. **A test that had never tested what it was named after.** "A hotspot with no
   dnsmasq is blocked" deleted the shim from `$BIN` and passed on a machine with
   `/usr/bin/dnsmasq`, because two unconditional firewall blockers were counted
   anyway. Removing them exposed it. The suite has `path_without` now, which
   builds a PATH where a command genuinely is not installed.

   by their own mutation: they searched the whole report, and `links` says
   "could not reach NetworkManager" too, so a different line satisfied them.
   They read the connectivity line only now.

   line as soon as there is more than one — with two, not at some width. So the
   old `hotspot list` parser returned EMPTY and the tool said "not sharing this
   machine's connection on any link" while two links were open. With one link it
   matched and printed nft's quotes. The predecessor's fix was right; its comment
   described the wrong failure and now says what was measured.

   `gvfs-gphoto2` are installed. `camera (PTP) tooling no` beside `cameras (file
   manager) yes` is two true statements, not a gap. The older evidence's
   "gphoto2" meant `gvfs-gphoto2`.
