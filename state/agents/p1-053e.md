
It builds both APKs, stands up `apex-agentd` + `apex-remoted` from the worktree
in their own XDG root, brokers the control socket to the phone, turns TalkBack
on, runs the instrumentation and restores TalkBack. **It never touches the live
runtime and stops its daemons by pid.** Round 1's result on the tip: **OK (24
tests)**, TalkBack bound.

**The system JDK 21 on the L16 is broken in a specific way** —
`/usr/lib/jvm/java-21-openjdk/conf/security/java.security` does not exist, so
every `MessageDigest.getInstance` throws `InternalError` and kills the Gradle
*wrapper* before a build starts. Use the unpacked root above. This is why
`JAVA_HOME` is not optional.

## FOUND

- **The suite cannot pair from a roadmap-dispatched agent, and that is the §7
  guard working.** This agent's cgroup is
  `…/user@1000.service/app.slice/apex-roadmap-resume.service`, so
  `origin::observe_pid` classifies the broker as **`scheduled-job`** and
  `apex-remoted` refuses to mint an offer: *"a scheduled-job request cannot pair
  a device"*. Baseline run on the tip `7f647470`: **24 tests, 8 failures**, all
  eight that sentence. Round 1 ran inside an interactive Claude Code session and
  got `local-terminal`, which is why it never saw this. **Fix: run the suite
  through `tests/in-login-session.sh`**, which mints a real PAM login session
  (verified: `0::/user.slice/user-1000.slice/session-19.scope`). It does NOT
  forward `JAVA_HOME`/`ANDROID_HOME` — its allowlist is `PATH HOME LANG LC_ALL
  TMPDIR APEX_* CARGO_* RUST* GITHUB_* CI ACTIONS_* XDG_{STATE,CONFIG,DATA}_HOME`
  — so wrap the export:

      tests/in-login-session.sh /bin/bash -c \
        'export JAVA_HOME=…; exec android/tools/run-device-suite.sh -s 192.168.1.98:35915'

- **`TerminalScreen` can never be hosted by `createAndroidComposeRule`.** Its
  `withFrameNanos` repaint loop keeps the Recomposer permanently busy, so
  `ComposeTestRule.setContent`'s own `waitForIdle` never returns —
  `IdlingResourceTimeoutException … hadRecomposerChanges = true`, measured, all
  three tests. `TerminalOnDeviceTest` hosts it through
  `ComponentActivity.setContent` and polls instead.
- **Landscape at font scale 2.0 on a Pixel 7a is a 63x7 terminal**, not 80x24.
  The PTY on the L16 agreed at 63x7. So the largest accessibility text size
  costs 17 of the 80 columns `Settings.terminalTextSp` says these TUIs lay out
  for. Measurement, not defect — recorded.
- **`TerminalView` is a bare `Canvas`, so TalkBack has nothing to announce on
  the terminal screen.** No glyph reaches the semantics tree. That is a real
  P1-060 C2 gap nobody had written down.
- **`MachineLink.request` returns an error reply as a STRING and does not
  throw.** The throw lives in the `Agentd.readX` parsers above it. A test that
  only caught `AgentError` around a hand-built `decide` frame saw no throw and
  reported "a phone approved a root operation" — it had not; the daemon refused
  in writing and nothing read the writing. Any new verb driven through
  `request()` directly must parse the reply.
- **There is NO relay client on Android at all.** `PairingService.handshake`
  says it in its own error text — "(and no relay client has been written yet)"
  — `:core` has no WebSocket code, and `Help.kt` tells the user the relay has no
  deployment. So "the relay leg on the device" is not a test to write against
  existing code: it is an RFC 6455 client in `:core`, a relay double the phone
  can dial on the L16, and `apex-remoted --relay` pointed at it.
- C1 names **approvals** too, and `p1-053d`'s evidence lists "no approve/deny
  round trip" as a third gap the dispatch does not mention. **A phone can never
  approve or deny** — `privilege.rs:1176` refuses `decide` from any non-local
  origin before the pending check — and `Approvals.kt` records that as a thing
  that deliberately does not exist. What a phone CAN do is list requests/grants
  and revoke, so that is the shape the device test must take.
- Round 1's findings are on `p1-053d.md` under CORRECTIONS, and two of them
  invert a criterion in our favour.
