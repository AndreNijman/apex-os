## Measured before writing anything

- `sudo -n true` works on the L16 — non-interactive sudo is available.
- **`smartctl -j /dev/nvme0n1` as an unprivileged user exits 2** and returns a
  document with only `json_format_version`, `local_time` and `smartctl`, where
  `smartctl.exit_status` is 2 and `smartctl.messages` holds
  `"Smartctl open device: /dev/nvme0n1 failed: Permission denied"`. A reader
  that keys on the absence of `nvme_smart_health_information_log` reports
  "no SMART data" for a disk that has plenty.
- **`sudo smartctl -j /dev/nvme0n1` exits 0 and also returns no health log.**
  smartctl with no action option does nothing; `-a` (or `-x`/`-H`/`-A`) is
  what asks. Exit 0 plus an empty document is the same trap wearing root.
- `fwupdmgr get-devices --json` answers as `andre` with no session bus at all
  (it uses the system bus). No polkit prompt.
- **`io` is not in the root cgroup's `subtree_control`** (`cpu memory pids`
  are), so no `io.max` file exists anywhere under `user.slice`. I/O budgets
  are not enforceable for a user-service agent on this machine as shipped.
- `apex-agentd.service` has no `Delegate=`, so systemd owns its cgroup and
  sub-cgroups are unsupported until a drop-in adds one.
- **Nothing in any Containerfile installs `fwupd`** and
  `rpm -q --whatrequires fwupd` says no package requires it — it rides in from
  `quay.io/fedora/fedora-bootc:43`. `apex update`'s firmware pass in `ops.rs`
  depends on a package the image does not own.
- `smartmontools`, `nvme-cli`, `udisks2`, `gparted`, `parted`, `gdisk` are
  installed explicitly by `Containerfile.core:1017`.
