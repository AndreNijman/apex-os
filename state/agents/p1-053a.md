## What the desktop side already offers (from p1-052's card, measured)

`apex remote pair --text` prints only the `apex-remote:` payload on stdout.
`apex remote devices --json` -> `id`, `name`, `public_key`, `paired_ms`,
`last_seen_ms`, `revoked_ms`, `requires_user_verification`, `last_path`.
`apex remote revoke <id>`, `apex remote status --json`. No `pair --json`.
The relay is deployed and verified at `apex-relay.andrenijman.com`; the wire

`noise.rs`, `identity.rs`, `relay.rs`) — that crate is the specification.

## The protocol, as read out of the crate (round 1)

- Socket opens with ONE plaintext byte: `P` (0x50) pairing or `S` (0x53)
  session. Everything after it is `[u32 big-endian length][Noise message]`,
  length <= 65535, refused before allocating (`apex-remoted/src/net.rs`).
- Pairing is `Noise_NK_25519_ChaChaPoly_BLAKE2s`; session is `Noise_IK_…`.
  Prologue for both is the literal bytes `apex-remote/1`.
- NK msg1 payload = `PairingRequest` JSON (`key`, `name`, `token`,
  `user_verification`). NK msg2 payload = `{"ok":true,"device":…,"machine":…}`
  or `{"ok":false,"error":…}` — a refusal comes back inside the finished
  handshake, so the client must always read msg2.
- IK msg1 payload is empty; IK msg2 payload is the machine name as raw bytes.
  An unpaired or revoked key gets **no msg2 at all** — the connection dies.
  EOF there means "not paired or revoked", and the two are not distinguishable
  by design.
- Frames: `[u8 tag][u32 BE channel][payload]`, MAX_PAYLOAD 65514. Tags
  0 Control, 1 Open, 2 Data, 3 Close, 4 Ping, 5 Pong. Control/Ping/Pong only on
  channel 0; Open/Data/Close never on channel 0. Unknown tag is an error, not a
  skip. A Control payload containing `\n` is refused in both directions.
- base64url **unpadded** everywhere; `key=` with padding must be REJECTED.
- device id = first 16 characters of the key's base64url text.
- rendezvous id = b64url(SHA-256(`apex-remote/rendezvous/v1` || desktop_pub)[..16]);
  relay URL is `{prefix}/r/{id}?role=guest`, WebSocket binary payloads carrying
  the same length-prefixed byte stream.

P1-053: maintainable modern architecture and first-party APEX design language;
QR onboarding that explains trust; multiple APEX computers; app lock via
biometrics/device credential; polished dark/light/dynamic colour; **no secrets,

pause/stop/reconnect/attach; colours match desktop semantics.

and an accessory row; scrollback, search, selection, copy/paste, reconnect,
orientation; works with Claude/OpenCode/Codex/Gemini TUIs unmodified;
low-bandwidth and reconnect behaviour tested.

NOT readable from app storage, rather than asserting that you put it elsewhere.
