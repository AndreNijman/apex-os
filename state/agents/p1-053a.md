## The protocol, as read out of the crate (round 1)

- Socket opens with ONE plaintext byte: `P` (0x50) pairing or `S` (0x53)
  session. Everything after it is `[u32 big-endian length][Noise message]`,
  length <= 65535, refused before allocating (`apex-remoted/src/net.rs`).
- Pairing is `Noise_NK_25519_ChaChaPoly_BLAKE2s`; session is `Noise_IK_…`.
  Prologue for both is the literal bytes `apex-remote/1`.
- NK msg1 payload = `PairingRequest` JSON (`key`, `name`, `token`,
  `user_verification`). NK msg2 payload = `{"ok":true,"device":…,"machine":…}`
  or `{"ok":false,"error":…}` — a refusal comes back inside the finished
  handshake, so the client must always read msg2.
- IK msg1 payload is empty; IK msg2 payload is the machine name as raw bytes.
  An unpaired or revoked key gets **no msg2 at all** — the connection dies.
  EOF there means "not paired or revoked", and the two are not distinguishable
  by design.
- Frames: `[u8 tag][u32 BE channel][payload]`, MAX_PAYLOAD 65514. Tags
  0 Control, 1 Open, 2 Data, 3 Close, 4 Ping, 5 Pong. Control/Ping/Pong only on
  channel 0; Open/Data/Close never on channel 0. Unknown tag is an error, not a
  skip. A Control payload containing `\n` is refused in both directions.
- base64url **unpadded** everywhere; `key=` with padding must be REJECTED.
- device id = first 16 characters of the key's base64url text.
- rendezvous id = b64url(SHA-256(`apex-remote/rendezvous/v1` || desktop_pub)[..16]);
  relay URL is `{prefix}/r/{id}?role=guest`, WebSocket binary payloads carrying
  the same length-prefixed byte stream.

### What is NOT verified, stated plainly

1. **Every keystore and BiometricPrompt behaviour is unverified on a device.**
   The headless rule forbids an emulator, and there is no phone. The two claims
   that carried this round were settled from primary sources instead:
   `KeyGenParameterSpec`'s AOSP javadoc ("This authorization applies only to
   secret key and private key operations") and the string inside the shipped
   `androidx.biometric` classes ("Crypto-based authentication is not supported
   for device credential prior to API 30"). Both had already been coded wrong.
   First contact with a real phone is the next place defects will be.
2. **The CI `android` job has never run.** `pull_request` is on `main` only,
   which this program does not touch. Its first execution is the `push` to
   `roadmap/v2.2` at landing, or `gh workflow run pr-validation.yml --ref
   task/p1-053a-android-2` before it. The `platforms;android-36` step is the
   likeliest first failure. The classifier itself was run, not read: `android/app/**`
   selects android alone, `android/core/src/test/resources/noise-vectors.json`
   selects rust **and** android, `docs/android/notes.md` selects neither.
3. **No relay leg.** `PairingService` is TCP only. `PairedMachine.relay` is
   stored and `Rendezvous` is implemented and tested in `:core`, but nothing
   opens the WebSocket — `NoRouteToMachine` says so in its message. A phone off
   the LAN cannot reach anything yet. This is the first thing P1-054 needs.
4. **Every UI string is hardcoded** rather than in `strings.xml`. P2-b's
   territory; noted so it is not discovered as a surprise.
5. `release` is unminified and unsigned. Nothing is published, and keep-rules
   written before there is anything to shrink are keep-rules nobody can justify.

### For whoever takes P1-054 / P1-055

* `Session` is `Closeable` and has `measureRoundTrip()`. `PairingService`'s
  socket read deadline is 20 s and **stays on after the handshake** — correct
  today, and P1-055 must clear it before attaching a PTY or an idle terminal
  dies every twenty seconds. The comment in `connect()` says so.
* The architectural rule the leak test rests on: **`:app` never opens a file.**
  Everything goes through `AppStorage` in `:core`, handed `filesDir` by
  `MachineRepository`. `tools/no-second-write-path.sh` fails the build if a
  second writer appears — which is why the display preference is a field on
  `MachineStore` and not a `SharedPreferences` file. Agent state and terminal
  scrollback must not become an exception to this.
* Both halves of every handshake in `InsecureStorageTest` run in-process over
  pipes, so a handshake that cannot complete **hangs** rather than failing.
  `@Timeout` and a bounded join are what turn that into a named red test; keep
  them on anything that adds another responder thread.
* Toolchain is unchanged from round 1 (see above) and is not in git.
