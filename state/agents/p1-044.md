## Defects found by reading, to be proven and fixed

1. `apex.nft` is not idempotent: it declares `table inet apex { ... }` with no
   preceding `delete table`, so a second `nft -f` appends the rules again.
2. `apply_sets` builds one `nft add element` per protocol. One malformed
   `.conf` fails the whole add, so a single bad exception silently drops every
   good one — and `cmd_reload` still prints "exceptions reapplied".
3. `cmd_deny` interpolates an unvalidated name into a path and `rm -f`s it as
   root: `apex firewall deny ../../foo` reaches outside `/etc/apex/firewall.d`.
4. The `forward` chain's comment claims podman is unaffected because it hooks
   "at their own priority in their own table". nftables evaluates every base
   chain at a hook; a `policy drop` in one is final regardless of another
   table's `accept`. Needs an empirical answer.
5. `udp dport 5355` / `tcp dport 5355` (LLMNR) are accepted on every interface.
