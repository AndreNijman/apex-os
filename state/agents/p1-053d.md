### Two shipped defects the device found on the suite's FIRST run

1. **Every pairing code advertised an IPv6 address no phone could dial**, two
   ways stacked. `format!("{ip}:{port}")` on a V6 gives nine colon groups and no
   brackets, so `splitHostPort` takes the whole string as a host and falls back
   to port 7717; and even bracketed, `main.rs` binds `0.0.0.0`, so nothing was
   listening. Invisible on dual-stack because the V4 address is tried first.
2. **The phone could not start the `generic` adapter at all.** The picker is
   `Hello.agents`, which lists it; the wire builder had no `args`, which is
   where its program goes.

### P1-051 C6 — observed, and the observation is stronger than a test

On first launch the app raises a `BiometricPrompt` before anything else:
`uiautomator dump` shows "APEX Remote / Unlock to see your computers / Touch
the fingerprint sensor / Use PIN". **An agent with full adb access, a
debuggable build and root-free shell could not get past it** — there is no adb
verb that presents a fingerprint on real hardware, and `Use PIN` wants the
owner's credential. That is the criterion demonstrated rather than asserted.

Consequence, stated plainly: **the live app's own UI could not be driven
end-to-end.** `LanEndToEndTest` therefore drives `PairingService` — the
production class — with a `PlainBox` in place of `KeystoreSecretBox`, and says
so in the file.
