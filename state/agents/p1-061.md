# p1-061 — Extend APEX capabilities to normal application permissions

apex-shell half. Branch `task/p1-061-app-permissions`, from
`origin/roadmap/v2.2`. Worktree `/var/tmp/apex-work/wt-p1-061`, shell worktree
`/var/tmp/apex-work/wt-p1-061-shell`.

## Criteria, quoted from roadmap.yaml

1. A design unifies or brokers filesystem, camera, microphone, screen capture,
   USB/device, network, sensitive-directory and secret access **where
   Linux/portal primitives permit**.
2. Flatpak and native apps can be represented **without pretending they have
   identical enforcement mechanisms**.
3. Settings → Privacy & Permissions shows effective capabilities and origin.
4. Revocation behaviour is explicit and tested.

Measured, not assumed, and the reason the model is shaped the way it is:

- **The enforcer is per capability, not per subject kind.**
  `io.github.cosmic_utils.camera` is a Flatpak carrying `devices=all`; it opens
  `/dev/video0` directly and lands on the same logind ACL a native binary does.
  `com.spotify.Client` has no `devices=all` and is portal-brokered. Both are
  Flatpaks. The tests assert the first two produce the identical sentence and
  the third differs.
- **There is no microphone portal in any version of xdg-desktop-portal.**
- **Which portal interfaces exist is a property of the SESSION.** Usb, Secret
  and RemoteDesktop are absent under `default=hyprland;gtk` and present under
  niri's `default=gtk;gnome`.
- **Hyprland, the default session, had no Secret portal at all.** Fixed here.
  Naming a backend overrides its `UseIn=`; proven on a private bus rather than
  assumed.
- **Hyprland and niri hand `zwlr_screencopy_manager_v1` to any client**, so the
  ScreenCast portal is not what stops a program capturing the screen.

## NEXT

Nothing is outstanding that this round left half-done. Three things a later
round could tighten, in the order they are worth doing:

1. **Measure whether a permission-store change reaches a RUNNING PipeWire
   client.** WirePlumber's `portal-permissionstore` module is enabled in the
   user profile (it is disabled only by the `mixin.systemwide-session` mixin,
   which `main` does not inherit), so a camera revocation probably does reach a
   live client — but nothing here measured it, because measuring it meant
   taking a camera grant away on Andre's machine. `Timing::Immediate` exists,
   is unreachable, and a test holds it unreachable. A VM with a v4l2loopback
   device would settle it; then that variant becomes usable for camera.
2. **Decide whether Hyprland should reach `gnome.portal` for Usb and
   RemoteDesktop.** Deliberately not done — see the tail of
   `hyprland-portals.conf`. It would start xdg-desktop-portal-gnome in a
   session with no GNOME shell, for backends that talk to Mutter, and an
   interface that exists and cannot answer is worse than one honestly absent.
   Needs someone to try it in a VM and watch a real USB request.
3. **Render the page.** `PrivacyPage.qml` has never been instantiated under a
   compositor: qmllint proved the syntax (with a deliberately broken copy as
   the negative control), node proved the logic, and `check-privacy-ui.sh`
   proved the wiring, but no run has drawn it. The only harness that could
   opens a window on Andre's desktop. `tests/run-popup-smoke.sh` already lists
   `privacy` among its nexus pages, so whoever next runs that suite
   deliberately gets the first look.

Unrelated debt found on the way, not touched: `tests/check-doc-verbs.sh`
reports seven `apex lid` verbs in the binary and in no document. That predates
this branch (P1-063) and is somebody's to claim.
