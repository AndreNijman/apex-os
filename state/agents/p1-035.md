## FOUND
- `File::open` on a FIFO BLOCKS until a writer arrives. The first version of
  the daemon handler opened first and checked the type second, so a path to a
  FIFO would have parked a daemon thread indefinitely, from any caller, with no
  privilege. Found because the unit test hung. Now: stat the path, refuse a
  non-regular file before opening, open with O_NONBLOCK, re-check on the fd.
- A grep pattern containing a newline is TWO patterns to grep, the second empty,
  and an empty pattern matches every line. `grep -q $'\n'` therefore always
  succeeds. The first run of the suite reported "nothing that arrived can submit
  the line" as FAILED on bytes that were correct.
- `Request::Signal`, `Remove` and `Prune` take no peer credentials at all, so a
  confined session (which has the control socket bound in, so it can publish
  events) can SIGKILL any other session, delete its transcript, or prune every
  exited session. Read from apex-agentd/src/main.rs's dispatch; not exploited.
  Reported, not fixed — outside these three items.
- The `apex agent send` verb has no shell-side surface. apex-shell's
  AgentHelpContent.qml already tells the user per-worktree test status and
  merge-conflict state are "on the roadmap" (that text is P1-036's to correct).
