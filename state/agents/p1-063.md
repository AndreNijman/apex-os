with no prompt. No polkit rule is needed and none was added.**

1. `/usr/share/polkit-1/actions/org.freedesktop.login1.policy` line 106:

   override touches the action.
2. `pkcheck --action-id org.freedesktop.login1.inhibit-handle-lid-switch
   --process $$` exits **0** (no `--allow-user-interaction`, so it could not
   have prompted). Andre's session is `Type=wayland Class=user Active=yes
   Remote=no`.
3. Held for real, as uid 1000, nothing on screen:
   `systemd-inhibit --what=handle-lid-switch --mode=block …` appeared in
   `systemd-inhibit --list` as `WHAT=handle-lid-switch MODE=block UID=1000`.
   Root can take it too (probed with `sudo -n`).

So the driver may run as either uid. It runs as **root** for a different
reason: the power-down half (`rfkill`, keyboard-backlight sysfs, DPMS) and the
guards' `Suspend()` would otherwise hit `org.freedesktop.login1.suspend`, whose
`allow_active=yes` degrades to `auth_admin_keep` the moment the caller is not
the active session — a prompt waiting to happen.

## The design, decided by the orchestrator — build this, do not re-litigate it

- **The primitive is a `handle-lid-switch` block inhibitor**, not an edit to
  `HandleLidSwitch=`. Dynamic, reverts when its holder dies, and leaves a
  machine with no live work suspending exactly as it does today. Static
  `HandleLidSwitch=ignore` turns every laptop bag into an oven.
- **"Live work" is measured, not a mode the user must remember.** A live agent
  session is the obvious signal and `apex-agentd` already knows about sessions;
  `apexd/apex-agent-core/src/lock.rs` is P0-015's lock-state policy and is the
  nearest existing thing. A manual pin covers everything else.
- **Guards are mandatory and must name themselves.** Lid closed is lid closed:
  no airflow. A thermal guard suspends anyway; a battery floor checkpoints and
  suspends rather than dying mid-task. Whichever guard fires must be recorded
  and reportable.
- **The VPN is the load-bearing half of the request.** ASSERTED, not assumed.
- **After reopening, the machine says what happened**: how long it stayed up,
  what ran, whether the VPN held, what it cost in battery.

## How to test it without a lid and without a window

The decision function for the matrix; one real `SW_LID` event, under an
inhibitor whose lifetime strictly encloses the uinput device's, for the
end-to-end. The injector emits `SW_LID=0` and destroys the device in a trap
*before* the enclosing inhibitor can drop, so a crashed injector cannot leave a
closed lid behind an unheld inhibitor.

**"Permission denied is not absence" applies with force here.**
