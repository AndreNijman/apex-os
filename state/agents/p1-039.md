## P1-041 — engine half DONE, pushed at `771095e`, `0c8b342`, `4135361` (apex-os)

`color` and `color-assign` verbs on `apex-display-apply`. `color` reports colord
reachability, the registered-device count, every display profile with its vcgt
verdict, and per output the EDID-derived colord device id, the assigned profile
and the HDR verdict. `color-assign` creates the device at `normal` scope if
absent then `device-make-profile-default`.

vcgt is parsed from the ICC tag table directly; a file that is not an ICC
profile answers `None` ("unreadable"), which is deliberately a third answer from
`False` ("no curve"). The device id is built from the EDID, not the connector,
so a profile follows the panel rather than the socket. HDR is read from the
CTA-861 extension blocks — extended tag 6 is HDR Static Metadata, extended tag 5
is Colorimetry.

**Stated plainly in the commit and here: the curve is NOT loaded into the
hardware.** Two independent reasons, both reported by name in the `curve` field:
no ICC loader is on the image, and on the wlroots compositors the gamma LUT is a
single slot APEX's own night light already occupies (Hyprland excepted — its
night light is `hyprland-ctm-control-v1`, a colour matrix, a different slot).
The honest deliverable is assignment stored and reported.

  this image in which PipeWire reaches 70.

So `30-apex-gaming-rtprio.conf`'s comment ("20 rather than PipeWire's 70 …
staying well below the audio stack means a busy compositor can never preempt
PipeWire") was false: the ceiling and the audio stack's effective priority are
the **same number**. And "can never preempt" was never established anywhere —
APEX passes `--rt` with no priority, so what gamescope requests is gamescope's
choice and is pinned nowhere in the repo. Same class as this program's recurring
finding, wearing "a number nobody re-measured".

**The number is left at 20 on purpose.** Raising it is a security-posture
decision (that file's own header calls realtime priority a DoS primitive), and
separating audio from the compositor properly means granting the audio stack
MORE, not the compositor less. **FOR ANDRE:** that is the decision to make, and
the latent trap is recorded in the file — adding the desktop user to `@pipewire`
puts them in `@pipewire` and `@wheel` both, `30-` sorts after `25-`, and
pam_limits' precedence for two group lines on the same item is **not documented
in `limits.conf(5)` on this image**. Untested, not known-safe.

from the image**, so quantum and sample rate are not readable on APEX at all and
