## FOUND
- **The ten remaining §13.2 names were exactly this unit's**, and all ten
  landed: `secret.create`, `secret.bind`, `secret.rotate`, `access.read`,
  `access.edit`, `tunnel.read`, `tunnel.edit`, `workers-ai.run`,
  `ai-gateway.run`, `ai-gateway.edit`.
- **Two of them hand back a credential, and §13.10 says they must not.**
  `POST /accounts/{id}/access/service_tokens` answers with
  `result.client_secret`, and `GET /accounts/{id}/cfd_tunnel/{id}/token`
  answers with the connector token as a bare `result` string. A provider cannot
  reach the store (`provider.rs` says so in as many words), so
  *"created service secrets enter apex-secretd directly"* could not be met
  without a seam. That seam is one additive field on `Performed`, not a new
  authorisation model.
- **Cloudflare Secrets Store really is write-only**: `secrets-store_value` is
  `writeOnly: true`, `x-sensitive: true`, "the API never returns this value".
  So P1-010's second criterion is about *not fabricating* plaintext, and the
  create/rotate value has to arrive some other way — the request **body**,
  the way `apex secret add` sends one, never a `Syntax::Text` parameter.
- **Three of these endpoints are PUT-replaces, not patches.**
  `PUT /ai-gateway/gateways/{id}` requires `rate_limiting_interval`,
  `rate_limiting_limit`, `collect_logs`, `cache_ttl` and
  `cache_invalidate_on_update` — so a partial edit must read first and send
  the whole thing back. Same for `PUT /access/apps/{app_id}` and for the
  worker-settings `PATCH`, whose `bindings` array is replaced wholesale.
- **CORRECTED (round 7): an AI Gateway run is NOT a different host.** The card
  previously said it was, and that the pin would force a second stored
  credential. It does not. AI Gateway's REST API page documents the gatewayed
  form of the *ordinary* call — `POST /accounts/{id}/ai/run/{model}` plus a
  `cf-aig-gateway-id` header, on `api.cloudflare.com` — and says the path form
  "also continues to work". Same host, same credential; the difference between
  the two operations is a header and a grant.
  **This is the one claim in this provider the pinned schema cannot check.**
  `workers-ai-post-run-model` declares two path parameters and *no headers*, and
  `cf-aig` does not occur anywhere in the 25MB schema — it neither documents nor
  contradicts this. Sources, now cited in the module note:
  `ai-gateway/usage/rest-api/` (the gatewayed call, model in the path),
  `workers-ai/get-started/rest-api/` (the ungatewayed one, `prompt` body),
  `ai-gateway/configuration/custom-metadata/` (≤5 entries, scalar values, `cf.`
  reserved — the three limits the metadata test asserts).
- **`apex-aid` cannot route anywhere, and it is not just a missing URL.**
  `apexd_core::ai::Backend` is a *compute* backend (`Cuda`/`Rocm`/`Vulkan`/`Cpu`),
  **and** the inference runtime is started under `bubblewrap` with
  `--unshare-net`, which its own module note calls the load-bearing flag. The
  backend cannot reach `api.cloudflare.com` because it cannot reach anything.
  So P1-009's first criterion needs something *outside* the sandbox to make the
  brokered call and hand the answer in — a design change in another crate,
  deliberately not taken mid-integration. What ships is the brokered route.
- **Three mutation pairs did not bite the first time, and the tests were what
  was wrong** — the exact defect class this unit was warned about:
  * a leaked project path passed, because the filter that makes a header value
    safe strips `/` as a side effect, so "contains no slash" and "is not the
    path" both hold while every directory on the way is in somebody's logs;
  * discarding the read-modify-write's read entirely passed, because the
    assertion asked about `collect_logs`, which the required-field fallback sets
    to `true` regardless — preserved and defaulted were the same observation;
  * `Effect::Read` on an operation that spends money passed, because nothing
    asserted otherwise. A `Read` grant could have run inference.
  All three now have assertions that bite. The double's gateway reply was
  changed to values no fallback could produce (`rate_limiting_limit` 42,
  `cache_invalidate_on_update` true, `logpush`/`retry_max_attempts` undefaulted).
- **A trap in the mutation protocol itself, worth carrying forward.** Restoring
  a mutated file with `cp -p` (or `shutil.copy2`) puts back the file's ORIGINAL
  mtime, which is older than the artifact cargo just built from the mutant — so
  cargo skips the rebuild and the next run measures **the mutant's binary
  against pristine source**. It showed up as a restored tree failing a test it
  had just passed. Restore with content-only `cp` and touch the file.
