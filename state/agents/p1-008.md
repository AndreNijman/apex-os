## FOUND
- **The ten remaining §13.2 names are exactly this unit's**: `secret.create`,
  `secret.bind`, `secret.rotate`, `access.read`, `access.edit`, `tunnel.read`,
  `tunnel.edit`, `workers-ai.run`, `ai-gateway.run`, `ai-gateway.edit`.
- **Two of them hand back a credential, and §13.10 says they must not.**
  `POST /accounts/{id}/access/service_tokens` answers with
  `result.client_secret`, and `GET /accounts/{id}/cfd_tunnel/{id}/token`
  answers with the connector token as a bare `result` string. A provider cannot
  reach the store (`provider.rs` says so in as many words), so
  *"created service secrets enter apex-secretd directly"* cannot be met without
  a seam. That seam is one additive field on `Performed`, not a new
  authorisation model.
- **Cloudflare Secrets Store really is write-only**: `secrets-store_value` is
  `writeOnly: true`, `x-sensitive: true`, "the API never returns this value".
  So P1-010's second criterion is about *not fabricating* plaintext, and the
  create/rotate value has to arrive some other way — the request **body**,
  the way `apex secret add` sends one, never a `Syntax::Text` parameter.
- **Three of these endpoints are PUT-replaces, not patches.**
  `PUT /ai-gateway/gateways/{id}` requires `rate_limiting_interval`,
  `rate_limiting_limit`, `collect_logs`, `cache_ttl` and
  `cache_invalidate_on_update` — so a partial edit must read first and send
  the whole thing back. Same for `PUT /access/apps/{app_id}` and for the
  worker-settings `PATCH`, whose `bindings` array is replaced wholesale.
- **An AI Gateway run is a different HOST.** The universal endpoint is
  `gateway.ai.cloudflare.com`, not `api.cloudflare.com`, and the framework pins
  a credential to the host it was stored for. That is the pin working, not a
  bug; the consequence is that `ai-gateway.run` needs its own stored credential.
- **`apex-aid` has no remote-provider routing at all.** Its `Backend` enum is a
  *compute* backend (CUDA/Vulkan/CPU), and its module note says "nothing here
  talks to `apexd`". So P1-009's "APEX AI service can route through Cloudflare"
  cannot be closed from inside the secret daemon.
