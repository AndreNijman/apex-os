## FOUND
- agent.sh's bash/zsh prompt parses `exit_code` with `${exited%%,*}`, which needs
  a trailing comma. It holds only because the daemon always writes `attached`
  after it. The fish and nushell prompts do not have that fragility. Left alone:
  three other agents are in this repo and it is not a live defect.
- tests/test-project-layout.sh hardcoded apexd/target/debug/apex, so it reported
  19 failures under CARGO_TARGET_DIR. Fixed in b5764d1. Seven other suites still
  have the same line; left alone as out of scope.
- A tmux pane in an early manual test genuinely started a claude session on
  Andre's live daemon (removed with `apex agent rm 5`; daemon untouched).
  Isolating TMUX_TMPDIR does nothing about what the panes execute. The suite now
  also fixtures XDG_RUNTIME_DIR and puts a stub apex first on PATH. Written up at
  errors-and-fixes/test-pane-started-a-real-agent-session-on-the-live-daemon.md.
- nushell 0.99.1 reads vendor autoload files in the REPL only: `nu -c` and
  `nu script.nu` do not. Proven both ways, including a pty-driven REPL assertion.
- nushell cannot express the APEX_NO_AGENT_ALIASES opt-out at all — `def`/`alias`/
  `extern` are parse-time, so one inside an `if` defines nothing. Documented
  `hide` instead of faking it.
- zellij has no way to start a session with a layout without attaching, so
  apex-mux does it in two steps (attach --create-background, then add the layout
  as a tab). Costs one leftover default tab.

- Sessions 6 and 7 on Andre's live daemon (`waiting_for_user`, `claude`, cwd
  `/tmp`, no project, both started 19:46:02) are NOT mine and I did not touch
  them — my suites fixture XDG_RUNTIME_DIR so they cannot reach that daemon, and
  their cwd is not under any mktemp dir I used. Most likely another concurrent
  agent's. Flagged rather than killed.
